# 第 12 周复盘：订单、事务与库存

## 1. 创建订单流程

从 CreateOrderRequest 到返回 orderId，依次发生了什么？

- 首先创建一个预订单，并扣除库存数据
- 如果扣除成功，进行订单插入，这里需要再次检查订单数量，避免超卖
- 根据返回数据，判断订单是否创建成功
- 再根据订单id，创建订单详细数据
- 整个数据处于事务当中

## 2. 事务边界

为什么 @Transactional 放在 OrderCreationService.create()？
这个事务覆盖哪些数据库写操作？

- 让创建业务的整个过程，sql语句都处于一个事务当中，要么同时成功，要么同时回滚失败
- 创建预订单，库存扣减、创建订单、创建订单详情

## 3. 回滚

订单插入或订单项插入失败时，哪些此前操作应回滚？
Spring 默认对哪些异常类型触发回滚？

- 创建预订单和扣除库存需要回滚
- 这个不知道

## 4. 防超卖

“先查库存再扣库存”为什么不安全？
条件更新 SQL 如何保证库存不会扣成负数？

- 读取的操作存在并发，所以在创建订单时需要同时查询库存
- 将查询订单条件添加到条件更新当中

- 主要还是解决数据暴露问题，同时让接口锲约更稳定
